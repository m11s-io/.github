# Contributing

Contributions should explain the problem and the intended behavior. For code
changes, include the checks you ran and note any checks that need GitHub Actions
or external services. Keep changes focused, update relevant documentation, and
preserve existing repository and release identities unless the change explicitly
addresses them.

Before submitting a pull request:

1. Read the repository's README and applicable project guidelines.
2. Run the documented local formatting, lint, build, and test commands relevant
   to your change.
3. Review the diff for generated files, credentials, permissions, and unintended
   changes to shared callers.

For organization-wide workflow changes, follow the shared workflow process in
[project guidelines](docs/project-guidelines.md) and state the affected callers
and rollout order in the pull request.
